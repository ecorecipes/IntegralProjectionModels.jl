Problem & Solution

The IPMProblem and IPMSolution types follow the SciML problem/solve convention. Construct a problem, solve it, then extract results.

IntegralProjectionModels.IPMProblem — Type
IPMProblem

Central problem type parameterized by trait types. Encapsulates all information needed to build and iterate an IPM.

Type parameters

  • S: AbstractIPMStructure (SimpleIPM or GeneralIPM)
  • D: AbstractDensityDependence (DensityIndependent or DensityDependent)
  • T: AbstractStochasticity (Deterministic, StochasticKernelResampled, StochasticParameterResampled)
  • K: Kernel type (AbstractIPMKernel or function for DD/stoch)
  • Dom: Domain type
  • U: Population state type
  • P: Parameters type
  • E: Environment state type

IntegralProjectionModels.IPMSolution — Type
IPMSolution

Result of solving an IPMProblem.

Fields

  • t: time steps
  • u: population state at each time (Vector of Vectors)
  • kernel_matrices: materialized kernel(s)
  • eigenanalysis: named tuple (lambda, stable_dist, repro_value) or nothing
  • retcode: :Success or :MaxIters
  • lambdas: per-step growth rates (for stochastic models)

source
solve(prob::CoupledIPMProblem, DirectIteration(); save_matrices = true, rng = nothing)

Iterate a coupled IPM one time step at a time and return a CoupledIPMSolution. With save_matrices = false the discretised kernel of each component and step is not kept.

The problem is solved with demographic stochasticity if its stochasticity is Demographic() or an rng is given (with Demographic() and no rng, the default random number generator is used). Individuals are then whole: the numbers in every class must be whole numbers, and each component's kernel must keep survival and births apart (a DiscretizedKernel, or PKernel and FKernel sub-kernels), with survival probabilities that sum to at most one down each column. Each step, for one component after the other, in the order of the system:

  1. the individuals of each class survive and move according to a multinomial draw from their column of the survival matrix, and give births drawn as Poisson numbers with means from the fecundity matrix (demographic_step! of StructuredPopulationCore);
  2. the component's expected inflows, if any, are drawn as Poisson numbers and added.

The rules are then applied to the drawn state as in the deterministic mode. Given the same rng in the same state, the draws are the same.

Coupled IPMs

Several populations, each an IPM, stepped together on the coupled-system engine that StructuredPopulationCore shares with MatrixProjectionModels.jl: scheduled events, substeps, rules and observables act on a PopulationSystem, and each component is stepped by its kernel for the step. A deterministic or a demographic run.

IntegralProjectionModels.CoupledIPMProblem — Type
CoupledIPMProblem(system, tspan; p = nothing, substeps = [], rules = [], events = [],
                  observables = [], normalize = false, inflows = Dict(),
                  stochasticity = Deterministic())

Several populations, each an IPM, stepped together. system is a PopulationSystem whose components carry their numbers per class in a vector. The model of a component is a kernel (PKernel, FKernel, CustomKernel, MatrixKernel, a sum of them, a MegaKernel or a DiscretizedKernel), a matrix, or a function (system, day, p) returning one of these, which is called every time step: this is how a kernel comes to depend on the other populations, through the system's state.

Each time step, as for a CoupledMPMProblem of MatrixProjectionModels.jl: the events that are due fire; the substeps run in order; every component is stepped by its kernel for the step, discretised by materialize, all from the same state; the expected inflows are added; the rules are applied together; and with normalize each component is scaled to sum to one.

inflows maps a component's name to a function (system, day, p) returning the expected number of individuals that arrive in each of its classes in a step (immigration, a seed rain), evaluated with the state the substeps left.

With stochasticity = Demographic(), or an rng given to solve, the step has demographic stochasticity: see solve.

IntegralProjectionModels.CoupledIPMSolution — Type
CoupledIPMSolution

Result of solving a CoupledIPMProblem, with the fields of a coupled solution of MatrixProjectionModels.jl: t, u (for each time point, the classes of every component by name), component_names, component_matrices (component_matrices[name][step] is the discretised kernel used at a step; empty with save_matrices = false), component_totals, substep_log, observables, event_log, rule_log and retcode. sol[name] is the total of a component at each time point.
